# ShadowUI submission checklist

Unchecked means not yet evidenced here. This is a handoff checklist, not a claim that submission or deployment happened.

## Product evidence

- [x] Run typecheck, unit tests, evaluation tests, production build and actual browser critical flow; save exact commands/results.
- [x] Show availability → calculated conflict → constraint-safe alternatives → explicit commit → persisted receipt.
- [x] Show a rejected stale revision and a blocked invalid commit.
- [x] Refresh and re-read persisted state; state the deployment storage boundary.
- [x] Show a second supported domain and an unfamiliar mixed-capability request.
- [x] Show unsupported external action handling without a false success message.
- [ ] Check keyboard operation, small viewport, English LTR and Hebrew RTL.
- [ ] Verify live AI separately if claiming it; offline fixtures prove only demo planning.
- [ ] Identify limitations in the submitted description and video.

Evidence: [local verification record](verification.md). Mobile/RTL passed; comprehensive keyboard and screen-reader testing remains open. These checks do not imply a submission video has been recorded.

## Submission package

- [ ] Confirm entrant/team eligibility and authorized representative.
- [ ] Select the actual primary track and justified mini-challenges.
- [ ] Provide judge-accessible repository, complete source and reproducible instructions.
- [ ] Choose public/open-source licensing or required private judge access.
- [ ] Upload a publicly viewable video under three minutes.
- [ ] Include English materials or translations, product description and actual tool feedback.
- [ ] Ensure judging access lasts through the evaluation period.
- [ ] Submit before October 23, 2026, noon PDT; use October 21 evening as the user's internal readiness target.

These package requirements and timing come from the [official rules](https://amazonappdev2026.devpost.com/rules), checked October 18, 2026. Recheck them before uploading.

## Honest claims and release hygiene

- [ ] Say “simulated Alexa+ host”; do not imply certification or device execution.
- [ ] Distinguish real MCP calls and ShadowUI server commits from external employer updates.
- [ ] Remove API keys, private conversation data and identifying device paths from shared artifacts.
- [ ] Use only media and dependencies with appropriate permission/license.
- [ ] Include observed friction and actionable feedback; do not invent SDK/device experience.
- [ ] Do not claim awards, ranking, measured user impact or broad general intelligence.
- [ ] Do not imply publishing this repository alone satisfies a separate open-source contribution requirement.
- [ ] Save final video URL, repository revision, tested URL and test results together.
